# 《分析学》项目工作流程

> **总则**：所有规则都必须写明设立的原因；当规则的原因失效时，规则也应同步失效并删除或修订。所有工作记录都必须服务于后续工作效率的提升；仅记录流水账、对后续工作无意义的内容没有保留必要，评估为无用时应清理。

维护日期：2026-10-19

本文件用于减少续写、修订、构建和交付时的重复摸索，只保留当前操作顺序、可复现故障和仍需处理的问题。内容组织以《写作规范》为准，技术体例以《格式规范》为准，主称与索引边界以《术语规范》为准，书目字段以《书目维护注意事项》为准；这里引用主管文件，不另存一套正文规则。

**设立原因与维护触发**：单一职责能避免多份规则相互漂移。具体数学审核状态维护在 `工作记录/审核进度.md`，当前结构维护在 `工作记录/计划纲要.md`，跨卷调用维护在 `工作记录/跨卷引用表.md`，文献实读范围维护在 `参考文献原文件/来源记录.md`。规则的适用任务、技术条件或主管规范改变时，同步修订或删除本文件对应项；故障不能再复现、其防错措施已由工具可靠承担、或记录已无后续用途时，删除重复经过，必要时仅保留仍有解释作用的根因。清理不得把尚未闭环的数学问题写成已解决，也不得改变正式审核轮数和定稿状态。

## 1. 开始工作与任务定界

**设立原因**：先明确目标和工作区状态，可避免误覆盖已保存内容、重复网络同步以及无关扩写；工作前查看临时积压能及时发现已影响空间、检索和续工的旧产物。以下步骤用于新任务或范围变化时；同一任务已核实且未变化的信息直接沿用。

1. 开始新任务前检查 `tmp/` 等项目临时目录的积压情况；达到第10节的提醒条件时，先向编写者建议优先清理，再按当前任务和既有授权安排工作，不因提醒而自动停止已授权工作。同一任务连续推进时复用未变化的盘点，不每轮重扫；年龄不能代替安全确认。
2. 查看 `git status`；需要接入远端变化时才拉取，有未提交修改时先判断是否会冲突，不直接覆盖。每天首次工作可以评估同步需要，同一天后续对话不机械拉取。
3. 确认目标卷、编、章、节和本次任务类型，阅读相关纲要、主管规范及未决问题，不自行扩大范围。
4. 结构或排版修改前检查主文件、聚合文件和输入链；确需回归比较时保留最近一次可用结果。比较结束且基线无其他用途后，按第10节先隔离确认安全再移除。

## 2. 编辑层级与单一真源

**设立原因**：下列操作约束分别防止单文件目录增加维护成本、共享宏多份漂移、标题与纲要脱节、路径迁移断链，以及稳定引用误指。文件组织和标题技术体例服从《格式规范》；结构已变更时随之调整这些操作步骤。

项目输入顺序为 `BookN.tex → FrontMatter / PartNN / Appendices / BackMatter → ChapterNN → SectionNNNN.tex`。卷、编、章聚合文件只承担相应层级的装配、标题与导语；节文件直接置于所属 `ChapterNN/`，共用宏维护在 `Shared/`。

- 新建节文件使用 `ChapterNN/SectionNNNN.tex`；不要恢复仅包含一个同名节文件的目录。批量迁移后核对独立编译根指令、全部 `\input`、仍有用途的文档路径及受影响分卷的构建。
- 改名先对照摘要、学习目标、全部一级节和章末小结，再同步实际 `.tex`、《计划纲要》和《审核进度》的当前名称，保留指向同一对象的稳定标签；改后核对页眉、目录和书签。仅翻译尚未核定的工作占位时，不把暂定名称写成已核定术语。
- 从纲要生成小节骨架时，按《格式规范》的层级、标签和选读宏落实；展示公式不生成小节。生成后核对输入链、实际目录节点及标签唯一性。可随时重写的一次性生成脚本不必入库。
- 依赖图依据实际证明和后文调用，只画直接而重要的前置关系。拆分选读节或调整主线边界前检查外部调用，保留仍指向同一数学对象的标签，为新增对象另设标签；同步纲要、聚合文件、章首路线、依赖图和跨卷引用表，再检查重复标签与未定义引用。
- 术语与标题处理先确认定义范围，再按《术语规范》操作；只授权标题修改时不顺带改正文。已核定主称才能同步相关当前台账，不能用旧稿名称抵消已核实的教材依据。

## 3. 初次撰写与初稿自检

**设立原因**：初稿曾因把纲要坐标当作完整教材而缺少技术桥；来源入库也不等于实际阅读。以下步骤帮助写足证明、例子和来源接口，同时避免把初稿自检混成未经启动的正式审稿。具体读者设定、陈述条件、习题、术语和引文要求见主管规范。

1. 开写前从来源记录与 `Shared/References.bib` 选出确实服务于本章的资料，区分主线依据、边界版本、中文术语及习题参考。只能核验目录或出版信息的资料不能承担定义、证明或具体版本的依据；不按固定数量凑资料组。
2. 列出尚需完成的证明义务：中心构造的输入与目标、主定理前置、容易略过的技术桥、边界情形、正反例及训练目标。采用特定版本、证明、反例或改编题时保留可定位的出处，写入相关来源说明，完成后只留下后续核对需要的信息。
3. 沿引用链检查先定义后使用、构造良定义与必要条件；对 `proofsketch`、“同理”“逐项验证”“适当”“标准方法”等候选逐处判断，不把关键词扫描当作数学检查。
4. 反查正文、后章和附录对习题的标签调用及“由章末题可知”等文字调用。正文必需的结论与证明移入正文，调用改指正文标签；原题保留标签并换成有新训练目标的题，补齐解答。可选应用或调用处已有完整证明的引用可以保留。
5. 核对相关术语、具名结果、资料推荐、citation key 和引文定位；其写法直接执行《术语规范》《写作规范》《格式规范》及《书目维护注意事项》，不在此重复字体、异名和书目条款。
6. 页数、字数、证明概要数或题数仅在能够诊断内容压缩、证明缺口或训练失衡时统计；不每轮固定生成，不为凑数字机械扩写。诊断解决后，把仍有用的缺口与措施归入主管文件，删除失去用途的统计流水。

首次撰写不自行启动正式数学审核；这只限制审稿轮次，不降低初稿完整性。必要编译、标签、输入链、明显笔误与逻辑自检仍应完成。章的当前状态及时更新到《审核进度》，初稿完成而未收到正式意见时为“待审核”，正式审稿已开始而未闭环时为“审核中”；具体总表字段与定稿条件以该文件为准。

**未决断言的保留原因**：核心定理、假设或精确版本尚待复核时，读者和后续工作者必须能区分已建立结果与待核输入。使用共享 `coreverification` 环境明确写出断言及问题，它不是定理环境，不能代替编号、引用或审核状态；通过复核后改回正式环境并删除高亮，被标记章节不得定稿。模型称谓随现行工具更新，不因名称过期而删除未解决的数学问题。

## 4. 处理审稿意见

**设立原因**：审稿意见也可能有数学或规范错误；至少两轮逐章审核用于减少同一阅读路径反复遗漏，横向格式检查不能代替数学复核。下列门槛只在正式审稿流程中适用，若编写者调整审核方式，应同步修改而不据旧规则增加轮次。

1. 逐条核查意见的数学正确性、必要性和规范一致性。正确且明确者修改，事实可疑者核实，规范冲突者给出依据并与编写者商议。
2. 《审核进度》保留能够支持续审和定稿判断的依据：实际阅读范围、所据版本、关键问题、处置、未决项和复核结论。无需为一次没有新问题的常规检查另写流水；重复经过可合并，已闭环且无复用价值的细节可清理，但不能由此虚增或抹除正式轮数。
3. 正式评价沿用退稿／大修／小修／接受；“小修后接受”须完成小修闭环。每章至少两轮逐章审核，且最新评价接受或小修后接受并闭环，才可定稿。
4. 术语、引用、排版等横向检查不计入逐章轮数；当前状态以进度总表为准，不让已失效的历史结论覆盖当前未决问题。

## 5. 编译与交付

**设立原因**：分卷构建避免卷级状态混用，隔离输出避免污染源码，完整工具链防止书目和索引只有标题或沿用旧条目，稳定性检查避免交付错链成品。以下步骤依赖当前 XeLaTeX、Biber、MakeIndex 与 TeXstudio 入口；工具链变化时应复核并更新，不永久照搬旧命令。可执行命令以 `README.md` 和构建脚本为准，样式以《格式规范》为准。

1. 从对应 `Book1.tex`、`Book2.tex`、`Book3.tex` 编译。TeXstudio 根文档的 `TXS-program:compile` 调用同目录 `build-BookN.bat -NoPause`；魔法注释变更后重新打开根文档。不要把某卷绝对路径写成全局编译命令。
2. 辅助文件输出到 `tmp/build/BookN/`；需要源码身份或回归比较时使用同轮快照与清单。XeLaTeX 开启 `-synctex=1`，PowerShell 将 `--output-directory=../tmp/build/BookN` 作为一个完整参数传入，避免相对反斜杠路径被误认成输入文件。
3. 先解决首个有效致命错误，再处理连锁警告。公共样式、编号或宏影响三卷时重编三卷；只改一卷正文时完整编译该卷；仅文档变化且源码、既有构建清单和成品身份相符时复用 PDF。
4. 完整工具链为首轮 XeLaTeX → Biber → 三类独立 MakeIndex → 后续 XeLaTeX 稳定轮次。每次 MakeIndex 只处理一个 `.idx`，以绝对路径传入 `Shared/analysis.ist`；空 `.idx` 清除该类旧 `.ind/.ilg`，非空时确认生成且最终日志实际读入。
5. 覆盖成品前检查致命错误、未定义引用／引文、重复标签、缺字及持续重编提示；三类索引分别确认 `0 rejected`、`0 warnings`。含引文时还须确认参考文献实际排出，不能仅凭 Biber 成功或引文编号存在判定通过。
6. 通过必要检查后，把同一 PDF 复制到卷目录与项目根目录，把 SyncTeX 复制到卷目录；卷目录副本供编辑预览，根目录副本供验收与发布，编辑生成物由 Git 忽略。只做隔离验证时保留结果于 `tmp/build/`，不覆盖成品；失败时保留上一份可读 PDF。
7. 编写者要求及时导出时，将已保存的完整内容接入正文并完成必要构建，不让扩写或非阻断排版提示无限拖延。轻微警告只有仍需处理时才保留位置、影响和待办，阶段交付不等于数学定稿；已有相应上传授权时再按第 11 节执行。

## 6. 检查范围与止点

### 6.1 按任务选择检查

**设立原因**：重复检查未变化的全书结构、字体和视觉页面会挤占正文修订时间，而完全跳过受影响检查会掩盖错误。检查随真实改动和当前任务触发，不把早期连续撰写安排永久当作后续专项审核的限制。

- 连续撰写任务以推进正文为主，做必要的逻辑自检、目标卷编译及引用检查。编写者已明确后续至少有两轮外部审核，因此当前应降低审查时间占比，不反复交叉审查已核过的内容，不为细小格式调整反复构建，也不逐章重测全部题头坐标、页眉或索引链接；新增少量引文不触发未变书目库的整库复核。该取舍适用于写作阶段，正式外审与最终排版另按当时范围开展。
- 正式审稿由编写者启动。已授权的读者视角、条件或结构专项按其实际范围完成，不能以“初稿只做最低检查”回避当前任务。
- 未改部分且原证据仍适用时沿用已有结果；发现新问题或相关工具、输入发生变化时再重查。字体专项检查实际受影响的样例，不由此自动开展全卷数学审稿。

### 6.2 读者视角复读

**设立原因**：有基础但会遗忘的读者不能靠熟悉结论补出稿中省略的动机、条件和技术桥。具体标准以《写作规范》的读者设定与陈述条件条款为准；本节只规定检查和处置方式。

沿正文学习顺序检查新概念的动机与算例、构造的输入和目标、前文所需版本及条件回忆、外部知识的局部说明、图表的解释作用，以及脱离习题后的正文证明链。定义和定理条件须逐个实际阅读，不能由关键词命中数替代；条件遗漏清单服务于修订定位，不机械按章凑数。

保留尚需执行或能避免复犯的发现：实际读过的范围、稳定标签或具体位置、读者卡点、解释不足的原因及处理方案。关键词检索、章首抽查、主证明链检查和全文复读须明确区分。问题闭环后可合并为可复用原则，已无后续用途的逐条经过删除。此类检查不增加正式数学审核轮数；实际数学错误另行核查，移题或正文修改后检查受影响的标签、题解、调用并构建目标卷。

### 6.3 结构与局部视觉检查

**设立原因**：源码、日志与结构数据通常能快速定位问题，抽取文本也可能制造假空格；局部渲染应补足这些证据不能判断的版面事实，而不是每次固定拍图。

连续写作优先用编译日志和必要的引用、输入链检查确认成品可用，不常规渲染普通插图、公式页、定理页或习题页。仅在绘制复杂图片、交换图时，按实际风险查看相关图像；不因轻微间距、普通分页或已有示意图而启动图片审核。书签层级或书前结构实际改动时，可作针对性的结构检查。详细排版与全书视觉审计留给外审反馈后的专项或最终定稿阶段。

引用空格、页眉间距、目录颜色和索引链接先检查源码边界及本轮 PDF 文本；若抽取文本与源码不符，读取字形与链接区域坐标，防止把抽取器空格误当实际排版。证据足够时停止检查。

## 7. 附录检查

**设立原因**：附录容易错误继承最后一个正文编的层级或锚点；不同职责的附录也不能机械套用同一教学审核。实际结构、编号、题页和摘要体例只在《格式规范》维护，这里保留改动后的检查动作。

附录结构变化后核对纸面目录与 PDF 书签的层级、唯一入口和独立目标，确认后记、书目、索引回到顶级；根据 `.toc` 目标名和实际页面核对，不能只看标题文字。涉及题页、空白页、首章页序或摘要首段缩进时，检查实际输出而不只看参数已设置。

数学要求不降低，审核按职责分两类：基础补充类着重定义、条件、证明闭合、正文调用和题解；高阶或研究选讲类着重概念边界、维数／正则性条件、深层输入状态、来源与推导闭合。实际采用类别写入《审核进度》，不按附录字母猜测；正文调用方式或附录职责变化时重新评估。

## 8. 文献采集与写作接入

**设立原因**：书目存在、能下载、见过目录与读到所用论证是不同事实；资料资格和定位核实能避免误引，写作接入与成品核对能避免空书目。资料门槛、例外审批、字段和推荐语写法分别以《写作规范》《书目维护注意事项》为准。

1. 先按纲要明确需要核实的内容，再检查作者、版本、正式发表信息、来源准确性及可读范围。合法可保存的原文件放入本地资料目录；不能下载时保留网址和实际可读范围，不能可靠核实内容者不承担相关数学论证。
2. 来源记录只保留后续定位、资格判断、边界版本或许可范围仍需的信息。局部例外不得扩大为全局取消门槛；目录不能作为定义或证明的依据。
3. 写作前对应内容与证明义务选择来源、citation key 及题目来源，写作中按主管规范说明资料用途和针对性出处；完整自证不靠密集引文代替证明。
4. 修改引文后核对键、实际引用版本、原文定位及语义位置，确认本卷书后实际排出需要的条目；按第 5 节完整构建。条目与来源没有变化时不重复采集或核验出版元数据。

## 9. 跨卷引用

**设立原因**：不同卷单独编译且编号会随结构变化，标签、内容概要和调用方向能避免猜错目标。《跨卷引用表》只保存当前调用接口，不积累已不存在的引用经过。

新增、改动或删除跨卷调用时同步维护引用处、被引用处、稳定标签、内容概要、当前显示编号与方向；结构变化后按对象与标签核对。前书引用后书若只是预告，正文和表中明确标记。漏登记或目标尚未核实的相关章节不得定稿；调用删除后清除对应过期行。

## 10. 临时文件与记录清理

**设立原因**：有效基线和复现证据能节省排障时间，过期截图、日志及逐轮统计会占用空间、增加检索成本，并诱使后续工作误用旧稿。及时评估和清理减少积压；先隔离、再确认、后移除保留了误判时的恢复机会，避免删去正在使用的输入、未接入正文的稿件或唯一证据。保留按后续用途决定，不按“曾经生成过”或年龄单独判定可删。

`tmp/` 用于构建、当前定位、回归比较或交付身份核验。正在处理的问题保留必要基线；当前源码能够重建、成品已更新、临时结果不再支持未决问题或回归且删除不影响续工时，清理旧结果。当前成品还依赖某份源码快照或交付清单证明身份时保留其必要信息，不一并当流水删除。

### 10.1 工作前检测与提醒

- 以各临时单元内部实际文件的最近改动、当前引用和运行中的任务判断，不能仅用顶层目录的时间戳；复制、读取和打开文件不一定更新该时间，因此时间信息不足时明确说明，不能据此声称知道上次清理日期。
- 本项目暂以连续14天没有实际文件改动的临时单元作为“长时间未评估”的提醒候选；这个阈值只用于避免旧产物长期无人检查，不是自动删除期限。发现明显空间压力、重复旧稿或过期构建积压时，不必等满14天。
- 达到提醒条件时，在开始工作前简要说明积压范围、可核实的时间或体量，并建议优先做隔离清理；尚未评估安全的目录只能列为候选。已经提醒且目录未变时不反复催促，按编写者当前安排继续。
- 临时单元完成使命时及时评估，无需等到提醒阈值。任务周期、存储压力或编写者要求改变时重评阈值；旧文件仍有明确用途时继续保留，不因过期提醒撤销其用途。

**设立原因**：实际文件与引用比目录日期更能反映旧产物的状态；提醒让编写者决定优先级，阈值则提供可执行的检查起点。年龄不能证明无依赖，重复提醒也会打断工作，因此检测、建议和删除分别处理。

### 10.2 先隔离确认安全，再移除

1. **定界并检查内容**：核对候选的真实绝对路径确实在本项目指定临时目录内，确认无正在写入或使用的构建、编辑器和任务；检查输入链、脚本、现行文档、交付清单及未决问题的引用。符号链接、重解析点、路径归属不明或无法确认的对象暂不处理，不跟随其目标移动或删除。
2. **先隔离**：把已初步判定无继续使用必要的候选移到项目内 `tmp/cleanup-quarantine/` 下独立命名的批次，避免覆盖已有批次；保留原路径与隔离路径的最小映射，便于恢复。移动前同时核实原路径和隔离目标路径，不跨项目操作，也不把整个 `tmp/` 连同隔离目录一起移动。
3. **确认安全**：在候选离开原位置后，复查当前成品、预览与必要源码仍存在，相关输入、任务和保留证据可正常使用。可能是构建输入的对象做受影响范围的验证；纯缓存或无引用旧日志不因此触发全书重编。发现依赖、遗漏稿件或唯一证据时，恢复该项并重新评估；遇到同名新文件不覆盖，先核对冲突。
4. **确认后移除**：只有上述检查明确证明不影响续工，才删除隔离批次中的已确认项。等待时间本身不等于确认；无法确认时保留隔离项或恢复，不能将候选直接删除。隔离映射在恢复或最终移除完成后随批次清理，不成为新的永久流水。

**设立原因**：原位检查可能漏掉隐性依赖，隔离后的验证能暴露它们并允许回退；最小映射服务恢复，已完成后继续保留便失去用途。隔离目录、验证方法随项目布局和工具改变同步修订，但“先隔离确认安全、确认后移除”的顺序按编写者要求保留。

工作记录清理仍先提取未决问题、有效决策和可复用措施，再清理冗余经过；相关临时证据的移除遵循本节，不新建一份清理流水替代旧流水。

## 11. Git 与 GitHub

**设立原因**：按逻辑单元提交能保留可恢复边界，按授权范围暂存避免混入其他任务，远端实测避免把本地提交误报上传。网络同步只在当前授权和实际需要下执行，不因旧日程自动推送。

- 提交前核对差异并排除临时构建、参考原文件、辅助文件及无关改动。共享文件已有其他任务内容时逐项暂存；PDF 若反映整个工作区，保留必要源码身份，不声称仅由本次提交的源码差异生成。
- 有未提交修改时，不用批量恢复或重置试探。先看明确路径的状态与差异，较大回退先保存可恢复检查点，只恢复核实的文件或块，之后确认没有连带丢失其他改动。
- 不每轮机械推送；编写者当前授权按章上传时，以正文、相关当前台账和通过必要构建的阶段 PDF 为提交单元，不要求先完成正式数学审稿。范围不含无关卷和临时文件。
- 既有远端为 `https://github.com/EverStarine/Analysis.git`，分支通常为 `main`；每次上传仍只读核对真实目标和范围，普通快进推送后检查真实远端哈希与本地 `HEAD`。用户改变仓库、分支或撤回授权时旧流程相应失效；文件本身不授权换仓库、强推、删除分支或上传无关资料。

### 11.1 上传故障分层

**设立原因**：进程未启动、安全审核、网络、认证和非快进冲突属于不同故障；错误归因会造成无效重登、重复确认或危险配置修改。本节只在对应现象重现并核实时适用，不能由历史案例推断当前故障相同。

1. `CreateProcess` 或安全审核在进程创建前拒绝意味着 Git 尚未执行，不据此判断 GitHub 认证失败。先核对 `git remote -v`、`git branch -vv` 及必要的真实远端，账号有疑问时只查看账号名称与仓库元数据，不读取或输出令牌。
2. 权限阻断时说明已有用户指令、目标、范围和真实检查证据；只有新证据才重新申请，不换工具或改安全设置绕过明确拒绝。Git 真正执行后再依返回区分网络、认证和非快进冲突，不用强推处理冲突。
3. 单次 TLS 连接意外中断可有限重试；不据此撤销已有授权，不关闭证书验证或重置凭据。
4. 只有核实全局配置指向无监听的本地代理、且当前工具不能核验签发者证书时，才在该次命令测试 `git -c http.proxy= -c https.proxy= -c http.sslBackend=schannel ...`；保留证书验证，不永久改变全局配置，不启动未知代理。环境或证书问题改变后，此处置不再适用。

## 12. 可复用问题条目的写法

**设立原因**：条目应帮助下一次定位、修复或判断失效，日期和操作经过本身不能承担这些用途。因此不规定“每次工作必须写记录”，也不只追加而禁止更新。

有长期用途的新问题并入现有同类条目；只在无法归并时新增。保留现象与适用范围、已确认根因或待核假说、可复用处理与必要验证、未决状态，以及何时删除或更新。文件位置用稳定标签或明确入口，易漂移行号只作辅助。日期、具体版本或哈希仅在能定位有效证据时保留；已解决且措施已由主管规则或工具充分承载的冗余条目删除，不为删除动作再建流水。

## 13. 单轮完成与阶段收尾

**设立原因**：明确止点可避免无限附加视觉、同步和清理工作；阶段正文接入与数学定稿是不同状态，不能由一次构建成功推定审核通过。

完成本次授权的源码修改、必要构建、受影响检查、当前状态维护和差异核对即可结束。视觉全检、推送和临时清理只在各自触发条件成立时执行；没有新信息或可复用发现的操作不另写记录。

整卷阶段收尾核对结构接入、标题覆盖、依赖与选读边界、相关主管规范落实、文风与图表需求、完整工具链及成品身份，并把未决问题留在当前台账。“写作阶段告一段落”不自动改变任何章的正式审核轮数或定稿状态；具体章仍须达到第 4 节及《审核进度》的门槛。

## 14. 可复用故障与仍需确认的事项

本节只保留尚能避免复犯或支持未决处理的信息；设立原因就是各条的根因和失败后果，适用技术条件消失时删去或更新该条。已经由前文和主管规范完整覆盖的字体试排、术语显示、索引标点及乘法记号经过不再重复保存。

### 14.1 内容覆盖了纲要却仍然提要化

- 现象：标题齐全但定义、证明和例子被写成等长摘要，技术桥不展开，习题重复正文。
- 根因：把纲要坐标误当作完成标准，把不启动正式审稿误当作不必写全初稿。
- 可复用措施：先列证明义务，再按中心构造和读者卡点展开；篇幅服从数学任务，正文所需结果不交给习题。诊断数量只用于定位缺口，正文标准见《写作规范》。
- 更新触发：若新问题来自其他压缩原因，补核真实原因；不保留旧章前后页数作为未来写作配额。

### 14.2 索引或书目工具成功但成品为空

- 现象：`.idx` 或 `.bbl` 已有条目，PDF 却只有标题；引用编号存在但没有实际书目条目。
- 根因：`imakeidx` 的 `noautomatic` 不会自动运行 MakeIndex，入口仍为空标题占位或遗漏 `\printindex`／`\printbibliography`，只检查进程成功而未检查实际排出。
- 可复用措施：按第 5 节运行完整工具链并检查入口、最终日志实际读入与成品目标；现有 `ANALYSIS-BIBITEM` 日志标记用于核对实际排版的文献键，`AtEveryBibitem` 在导言区登记。不能把缺目标的引文链接简单删除来掩盖空书目。
- 更新触发：索引、书目包或自动验收机制变化时复核此根因和检测接口；工具已充分阻止且无需人工解释的旧验收流水删除。

### 14.3 配置已改但某些字符仍继承旧样式

- 现象：列表已设正体，西文字母或罗马数字序号却仍斜体；摘要段落参数已设置但首段不缩进。
- 根因：后执行的字母切换覆盖前面的列表样式，或段落参数不作用于首段。源码出现设置命令不能证明最终生效。
- 可复用措施：检查生效顺序与共享环境，按《格式规范》选最小代表样例验证实际输出；只重复外围设置不能解决覆盖问题。
- 更新触发：字体、列表或摘要实现变化时重新定位；不保留已撤销试排方案的时间顺序。

### 14.4 PDF 抽取或链接动作造成误判

- 现象：抽取文本出现源码没有的空格，或设置 `pdfnewwindow=true` 后普通网页仍没有新窗口属性。
- 根因：抽取器会合成空白；普通 URI 动作不使用远程 PDF／启动动作的该属性。
- 可复用措施：空格疑点检查字形与链接坐标；网页保留标准 URI，行为和技术边界见《书目维护注意事项》，不叠加无效配置或 PDF JavaScript。仅凭抽取文字或某个阅读器行为不扩大改动。
- 更新触发：PDF 驱动、动作类型或验收工具变化时复核，不能把当前边界作为所有未来格式的绝对结论。

### 14.5 同目录预览、SyncTeX 与源码身份

- 现象：根目录 PDF 可读，TeXstudio 却找不到同目录预览或定位失败；提交所含差异与 PDF 实际源码不完全一致。
- 根因：只复制根目录成品、未启用 SyncTeX、查看路径错误，或在包含其他已保存改动的工作区构建。
- 可复用措施：按第 5 节统一预览入口与输出，隔离快照交付时核对 SyncTeX 的源码路径；保留当前成品确实需要的源码身份信息，不把同一份 PDF 误述为只对应部分提交。
- 更新触发：编辑器、交付方式或路径变化时重验；旧成品哈希、已失效快照和按轮构建经过不属于本故障条目。

### 14.6 书签格式代码泄漏或反复报告待重编

- 现象：编级书签出现颜色、字体命令残片，或 PDF 字符串看似相同却每轮报告标签变化。
- 根因：ctex 的目录编号展开了带字体和颜色的题页设置；原始 Unicode 希腊字母在 `unicode-math` 写入和回读辅助文件时类别码不同。
- 可复用措施：保持共享 `\CTEX@part@tocline` 的纯文本编号分支，数学题名用 `\texorpdfstring` 提供完整书签文本，希腊字母采用共享 `\AnalysisPdf...` 可展开宏。修改后核对实际书签文本及辅助文件稳定性，不能只判断正文标题可见。
- 更新触发：ctex、数学字体包、标题宏或书签写入方式变化时复核补丁；原始缺陷消失则删除对应补丁要求，不永久要求保留内部实现。

### 14.7 范数索引中的竖线被处理器误解

- 现象：MakeIndex 可以退出成功，但范数词条被拒收、损坏或缺失。
- 根因：索引参数经过 TeX 与 MakeIndex 两层解析，裸竖线可能被识别为页码处理分隔符。
- 可复用措施：索引参数的防错写法按《格式规范》的索引条款处理，并检查 `.ilg` 拒收与警告以及实际词条；不靠进程成功判断全部收录。
- 更新触发：索引后端或转义机制变化时重新核实该风险；不要由索引特例全局改写正文范数记号。

### 14.8 旧断行待办须按当前稿确认

- 原待办：第一卷第 15 章 `Section1501.tex` 曾有定义段轻微超行，低优先级断行提示未消除。旧行号与超行数不能证明当前稿仍有问题。
- 保留原因：原记录未给出闭环结论，直接删除会把未确认状态伪装成已解决。
- 后续动作：下一次该处版式修改或专项排版时按定义段定位，核对当前日志与必要局部输出；若已消失，删除本条，若仍存在，把实际位置和处理转入当前待办。它不阻断其他无关任务，也不据此重复整卷构建。
